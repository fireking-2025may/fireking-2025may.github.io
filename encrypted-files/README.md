# Encrypted text vault

Open `index.html` through GitHub Pages (or another HTTPS/static web server) and enter the separately shared vault password. All key derivation and decryption happen in the browser with the Web Crypto API. The password is not stored in this repository.

Files under `vault/` are JSON text envelopes containing only a random salt, IV, algorithm metadata, and AES-256-GCM ciphertext. The decrypted JSON payload has this shape:

```json
{ "name": "example.txt", "content": "Private text goes here." }
```

Editor template databases use this reusable decrypted payload format:

```json
{
  "type": "editor-defaults",
  "schemaVersion": 2,
  "templates": [
    { "id": "91AF3C7E5B2D814F", "header": "Template label", "blocks": [
      { "id": "A71F932C5B2D814F", "type": "paragraph", "runs": [{ "text": "Reusable content." }] }
    ] }
  ]
}
```

`type` is exactly `editor-defaults` and `schemaVersion` is `2`. IDs are automatic, non-editable 16-character values drawn from `123456789ABCDEF`. Templates use the document editor's closed paragraph, subordinate heading, nested list, table and published HTTPS-image block schema, including rich runs, review highlights and validated links. Unsupported HTML, arbitrary styles, data URLs and unsafe links are rejected.

## Publishing editor defaults

1. Open `defaults-editor.html`, select the current canonical `vault/8f3c1a7e4d92b605.json`, and keep an untouched backup outside the live vault directory.
2. Unlock with the current password and review existing templates. Version-1 body records receive a one-time, reviewable migration; their displayed text is preserved while internal IDs change.
3. Edit headers and structured content. Add templates only through the UI, then validate and preview every changed template.
4. Choose and confirm the output password. Download the result as `8f3c1a7e4d92b605.json` and replace `encrypted-files/vault/8f3c1a7e4d92b605.json`. Do not edit `manifest.json` unless its opaque filename intentionally changes.
5. Run `cd UBTA`, `npm test`, and `npm run build`.
6. Open `UBTA/dist/index.html`, unlock **Default update** with the output password, insert every changed template and inspect its paragraphs, lists, tables, links, highlights and headings. Undo immediately and confirm the complete insertion is one history action.
7. Search the repository for distinctive plaintext, review the Git diff, and commit the canonical encrypted file and rebuilt editor together.
8. Publish through the normal GitHub Pages workflow. Verify the homepage link, management page and live Steps Plan Editor in a clean browser session.

The canonical JSON above is the only manually maintained defaults ciphertext. `UBTA/src/editor/default-template-data.js` is generated by `UBTA/scripts/build.mjs`; never edit it independently.

Each file uses a unique 16-byte salt, a unique 12-byte IV, and 310,000 PBKDF2-SHA-256 iterations. The filenames inside each payload are encrypted; `manifest.json` exposes only the opaque storage paths needed by the static page.

## Important limitations

- Serve the directory over HTTPS or `localhost`; browsers may disable Web Crypto or `fetch()` on `file://` pages.
- Anyone can download the ciphertext from a public GitHub repository and attempt passwords offline. Use a long, randomly generated password and share it outside the repository.
- Git history retains old encrypted files. Rotate the password and re-encrypt every file if the password is exposed.
- This page protects file contents at rest; it does not provide user accounts, access revocation, or protection from malicious changes to the hosted JavaScript.
